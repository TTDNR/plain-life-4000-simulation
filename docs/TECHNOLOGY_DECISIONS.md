# 技术决策记录

## 0001 Phase 1 审计工具使用 Python 3.12 标准库

日期：2026-09-25
状态：已接受

背景：

需求要求在启动长期模拟前，提交环境资源清单、开局生存核验和初始化一致性检查。没有这些
结果时，长期模拟不能开始。该阶段需要可复算、无网络、无额外依赖的门禁工具。

候选方案：

- 只维护 Markdown，人工检查。
- 使用第三方 JSON Schema、数据框或测试框架。
- 使用 Python 3.12 标准库实现结构化审计。
- 先选择完整模拟引擎，再在引擎内实现门禁。

决定：

Phase 1 使用 Python 3.12 标准库，读取 `data/phase1/*.json` 并输出 Markdown 或 JSON
审计报告。此决定只覆盖长期模拟前的离线门禁，不选择长期运行语言、引擎、数据库或渲染方式。

原因：

- 需求已经明确要求可检查、可复算的三项前置结果。
- 标准库足够完成结构校验、引用校验、汇总和退出码控制。
- 不需要安装包，不污染项目本地依赖，也不引入共享缓存。
- 纯 JSON 输入可以由后续需求方或生成器提供。
- 审计器可以独立替换，不绑定未来模拟实现。

代价和风险：

- 当前不是完整 JSON Schema，字段约束由 `tools/phase1_audit.py` 维护。
- 若要校验大规模逐格世界或 4000 人完整快照性能，可能需要在真实需求明确后更换实现。
- Python 审计器不能承担长期模拟运行时职责。

后续验证：

- 每次修改 `data/phase1/*.json` 后运行单元测试和审计命令。
- 长期模拟引擎选型必须另立决策，记录性能、空间模型、持久化和观察接口的取舍。

## 0002 Phase 1 专项模型使用 Python 3.12 标准库

日期：2026-09-25
状态：已接受

背景：

需求要求在启动长期模拟前生成固定世界和 4000 人初始人口，并核验饮水和食物等基础生存
行为、探索和迁移。当前没有长期帧率、并发规模、交互方式或部署目标，无法据此选择正式
模拟引擎。专项核验必须可复算、无网络，并且不能把测试状态写入正式初始快照。

候选方案：

- 立即选择 Unity、Unreal、Godot 或其他完整模拟引擎。
- 引入 NumPy、Pandas、数据库或第三方代理框架。
- 使用 Python 3.12 标准库实现确定性的短期核验内核。
- 只做电子表格估算，不建立逐日空间消耗模型。

决定：

使用 Python 3.12 标准库实现 `plain_life` 包，包括：

- 100 x 50 的 50 平方公里确定性环境生成。
- 季节、降雨、蒸发、资源再生和消耗。
- 4000 人、1000 家庭的人口与技能初始化。
- 家庭劳动分配、饮水、食物、遮蔽、火、工具、探索和迁移核验。
- Markdown/JSON 报告输出。

该决定不选择长期模拟引擎、数据库、可视化框架或网络架构。

原因：

- 现有需求只要求可检查的开局核验，没有长期性能或交互指标。
- 标准库足以处理当前 5000 格和 4000 人规模。
- 固定种子和状态指纹可以直接复算世界。
- 模型可以随着后续人物决策需求替换，不把测试规则固化为正式模拟器。

代价和风险：

- 当前 365 天专项核验约需两到三分钟，不适合大规模参数扫描。
- 逐家庭规则是简化模型，不能代表完整人类决策。
- 长期代理数量、空间查询和事件频率明确后，可能需要迁移到编译语言、数据引擎或 ECS。

后续验证：

- 当长期模拟需求明确时，另行评估运行时引擎、持久化、性能和多进程方案。
- 在人物决策需求补齐前，不得把本专项模型称为完整人类社会模拟。
